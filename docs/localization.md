# Localization

Administrators can set the site language, date format and clock under **Settings → System → Site display defaults**. Signed-in users can override any of those values under **Settings → Preferences**. Each field can independently inherit the site default. The unconfigured site uses the browser language (with English as a fallback), the language’s date format and a 24-hour clock.

The sign-in and installer language pickers are available before authentication. For visitors, an explicit choice takes precedence over the language cookie and the site language. The installer can run before the site defaults exist. Account preferences are stored with the account, so a visitor's language cookie has no effect on the signed-in interface.

Notification text generated by Causette uses the recipient’s saved language, then the site language, then English. Causette stores the text at creation time, and the notification history displays the saved text. Message previews retain the sender’s original text.

The SMTP test email and administrator registration alert follow the same language order. Each administrator receives a separate registration email in their own language. Verification, password reset, address change and email sign-in codes use the language of the account, including when the account is signed out.

Browser action errors use the authenticated viewer’s language when the action prepares a translated response. Public bot API error text and machine-readable codes remain stable. Group and call history localize recognized system events for the viewer. Legacy event text is preserved when its structure cannot be identified reliably. The sidebar, typing indicator, retained account labels and text under archived messages also follow the viewer’s language. Native browser prompts and technical diagnostic values use the browser or provider wording.

Numeric dates support day/month/year, month/day/year and year-month-day. The clock supports 24-hour and 12-hour display. These settings preserve the account’s existing time offset and the stored UTC timestamps. Changing the display language leaves stored messages, poll questions, options and names as written.

The French emoji picker loads names and search terms from the local `public_html/assets/locales/emoji-fr.json` file when first opened. The file covers the Unicode emoji present in the packaged OpenMoji drawings when CLDR supplies an annotation. Other drawings use a localized code label. Existing search terms and exact glyph searches remain available. No browser request is sent to Unicode or OpenMoji.

To regenerate the file, run `node scripts/generate-emoji-annotations.mjs` to see the pinned input URLs and filenames, then run the same command with the directory holding those inputs. The script checks all three source digests and copies the Unicode license notice into the generated asset. [Unicode CLDR JSON 48.0.0 source](https://github.com/unicode-org/cldr-json/tree/4d06be52b51bb2f75688d0abe55c52a66afed790)

## Add a language

Add its code and display name to `public_html/app/locales/languages.php`. Use a lowercase language code such as `es`. Copy the catalog files from `public_html/app/locales/en/` to a directory with that code. Keep the keys and the named placeholders, such as `{creator}`, and translate their text. Missing entries fall back to English.

The catalogs are PHP arrays of plain UTF-8 strings. English and French ship together. User interface templates use `Locale::html()` for text and HTML attributes. Use `Locale::text()` when the caller is responsible for escaping, for example when building data for the browser. Send browser catalogs through the HTML-safe JSON encoder. Browser code uses `uiText()` for shared messages and `chatLabel()` for poll and pin labels. Page scripts that execute as the document loads receive their labels in the page because the shared browser scripts are deferred. Escape strings before adding them to an existing HTML template, or use DOM text properties.

Provide whole sentences with named placeholders when a translation needs to reorder words. Vote counts use the browser's plural categories and number formatting. Add the categories used by the language and keep the `other` form as a fallback. Add month abbreviations and date patterns to the `dates.php` catalog for PHP-rendered timestamps. Browsers use their native `Intl.DateTimeFormat` for language-specific dates.

Run `php tests/localization.test.php` to check catalog parity, placeholders and literal key references in the PHP and JavaScript sources. Run `php tests/localization-surfaces.test.php` for server-rendered text and runtime messages, and `php tests/error-localization.test.php` for HTML, JSON and the public bot response contract. Run `node --test tests/browser-localization.test.mjs tests/emoji-localization.test.mjs tests/chat-banners.test.mjs` for search, browser permissions, the emoji picker and live conversation text. The Chromium package localization scenario also checks the delivered French annotations.
