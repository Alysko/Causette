# Functional coverage

This inventory maps each inherited capability to its maintained application surface and development checks. The browser fixtures use an isolated HTTPS installation with synthetic accounts and a database created for the run. Scope the results to the executed checks and database engines recorded for a package. Provider fixtures exercise application behavior with controlled transports. Hosted acceptance and live provider delivery require separate evidence.

| Requirement | Maintained surface | Development coverage and limits |
| --- | --- | --- |
| FUN-01 Accounts and invitations | Registration and the invite settings panel use `AuthController`, `HomeController`, and `invite_codes`. | `mfa-lifecycle.test.php` exercises registration, invitation consumption, competing claims, rollback, and referrals. `social-lifecycle.browser.cjs` exercises invitation generation, concurrent requests across independent sessions, quota enforcement, ownership, and revocation. Automatic group joining needs dedicated coverage. |
| FUN-02 Authentication and recovery | The login, email verification, MFA, password recovery, and session routes remain available. | `mfa-delivery.test.php`, `mfa-lifecycle.test.php`, `password-recovery.test.php`, and `session-lifecycle.test.php` cover refusal, recovery, and session transitions. Hosted SMTP delivery remains a separate check. |
| FUN-03 Account and profile settings | Profiles, account settings, avatar controls, the user directory, and availability status use the original web routes. The settings index groups actions into icon-led lists. Display preferences offer dark, light, and blue-orange themes per account. | The theme fixture checks compatibility with older preferences, account isolation, and invalid input. A local Chromium rehearsal checks the packaged lists, keyboard activation, saved themes, and sampled contrast. Username history and all presence states need more end-to-end coverage. |
| FUN-04 Friends and discovery | Search and relationship mutations use `/api/users/search` and `/friends/*`. | The social scenario checks discovery, request, cancellation, single-notification acceptance, favorites, removal, and the effect of removal on direct messages. |
| FUN-05 Messaging | Personal and group routes, history, message editing, replies, pins, search, and indicators use `ChatController`, `ApiController`, and the chat view. Press Up in an empty composer to edit your latest message when its edit action is available. An unsuccessful save leaves the draft open for another attempt. | JavaScript tests cover the shortcut, timeline refresh during edits, and save failures. `message-mutation.test.php` checks authorization, group deadlines and input on the edit and delete actions with an in-memory database. Browser acceptance for the permissions and history pagination remains separate. |
| FUN-06 Group governance | Create a group from the conversation sidebar on desktop or from the mobile conversation menu. Groups start private. Owners and administrators can rename them and choose private, requestable, or public visibility in the conversation menu. Group actions use `/api/chats/group/*`. | The social scenario checks creation, rename, visibility, join request and cancellation, denial and approval, moderation, removal, ownership transfer, and deletion. Concurrency and the full role matrix need separate coverage. |
| FUN-07 Attachments and emojis | The upload, download, expiry, and deletion controllers use private storage. The composer and reaction pickers share 75 common Noto 3D emoji with default yellow faces and hand gestures. Messages and reaction badges reuse those images. Stored emoji outside the shortlist use the bundled OpenMoji images. | `attachment-upload.test.php`, `attachment-access.test.php`, and the payload browser scenarios cover file validation, budgets, authorized downloads, expiry checks, and emoji rendering. The emoji regression checks shared images, localized search and historical emoji on a mounted site. Validate provider filesystem behavior on the final host. |
| FUN-08 Calls | The browser uses authenticated call routes and WebRTC for media and signaling. Users can select and remember separate webcam and screen sharing profiles. Eco mode requests 720p at up to 25 fps. Actual capture depends on the browser and device. | `calls.browser.cjs` covers direct-call decline, retry, answer and hangup, and a two-party group call with simulated devices. A separate mode verifies that both browsers select a relay candidate and receive media through authenticated coturn. `call-signal-boundary.test.php` and `call-signaling.test.mjs` cover signaling, TURN credentials and webcam constraints. `call-video-preferences.test.php` covers preference validation, CSRF and account isolation. Real devices and relays across separate networks need browser acceptance. |
| FUN-09 Polls | Group polls support whole durations of 1–24 hours or 1–60 days. The composer converts the value when changing units. A partial day rounds up, and switching to hours caps the value at 24 hours. Existing polls retain their expiry. | The poll draft and interface fixtures check the limits and unit conversion. The packaged poll scenarios also cover creation, option count, draft handling, voting, and expiry. Concurrent update behavior is a separate check. |
| FUN-10 Posts | Posts, feeds, reactions, deletion, and search use `PostController` and the posts/search views. | The packaged reaction and post-search scenarios cover reaction rendering and ordered search results. The entire feed and deletion matrix needs end-to-end verification. |
| FUN-11 Notifications | The notification rail slides in and out and hides two seconds after the last entry disappears. It skips the transition when reduced motion is requested. The bell can still open an empty history. In-app history, sound and desktop preferences, and optional Web Push use notification routes and the service worker. | The interface fixture checks the hide delay and cancellation when a new entry arrives. A local Chromium rehearsal checks the desktop and mobile transitions. Browser tests activate the scoped service worker at `/api` and `/community` and drive a synthetic push event. Live provider delivery and native system notifications remain open. |
| FUN-12 Administration | The user directory, relationship tree, reports, trash, and administrative settings use the dedicated controller routes. | The social scenario checks role changes, bans, report processing, tree and trash access, permanent group deletion, and account deletion options. Check complete storage-statistics and reauthentication coverage separately. |
| FUN-13 Provider settings | SMTP testing, CAPTCHA and Web Push configuration use the settings panel. Optional services use explicit operator configuration. | `smtp-transport-fixture.sh` exercises authenticated SMTP with implicit TLS and STARTTLS against an isolated local service. The Push fixtures and packaged CSP checks cover attempted delivery, provider configuration, and policy. Production credentials and delivery through a hosted provider require separate verification. The automatic updater requires an explicitly configured Causette release source. |
| FUN-14 API keys and bots | Reveal-once key provisioning and the documented `/api/bot/send` endpoint preserve bot use. | `credential-storage.test.php`, role and access fixtures, and packaged bot attribution cover digest-only storage, key lifecycle, and message labeling. Non-bot capabilities require an explicit contract. |
| FUN-15 Browser behavior | The front controller and browser scripts support responsive navigation at the configured canonical origin and base path. The poll and group settings dialogs scroll within the space available above the on-screen keyboard. | Packaged account, mounted navigation, and call scenarios check navigation and UI state. `mobile-chat-dialogs.browser.cjs` checks both forms with a reduced visual viewport in Chromium. Native iOS and Android keyboard behavior and the complete hosted matrix need further verification. |
| FUN-16 Feature accounting | The table records supported upstream surfaces and their maintained counterparts. | `/api/servers` and `/api/channels/{server_id}` are explicitly labeled placeholders. The distribution does not describe those routes as a workspaces or channels feature. |
| FUN-17 Navigation and personal preferences | Sidebar customization, preferences, notifications, and call controls use the corresponding views and settings routes. The Unread filter shows direct and group conversations with unread messages and remembers the selected filter in the browser. | JavaScript tests cover the filter, live unread counts, and its empty state. The packaged preference, notification, account, and call scenarios check defaults, account overrides, and key interactions. Each media preference and browser combination needs a dedicated check. |
| FUN-18 Lifecycle and moderation | Conversation membership, private attachments, group trash, bans, and retained messages use server-checked transitions. The ordinary edit and delete actions refuse messages and submitted attachments in group trash. | The social test covers group and account lifecycle. The attachment fixtures cover file state and access, and `message-mutation.test.php` checks that the ordinary routes preserve archived content. Bulk account deletion and filesystem recovery need separate coverage. |
